SynthForge

    Get started

    Nothing here needs a database except run and export-db.

    Install

    pip install -r requirements.txt
cp example.env .env

    Without a database

    # plan only, sub-second
python data_pipeline.py --dry-run

# render DDL + payloads
python data_pipeline.py --offline

# serve with no database
python api_server.py --offline

    With a database

    # full run, then verify
python data_pipeline.py run \
  --verify-writes

# 1% volume, fast loop
python data_pipeline.py run \
  --scale 0.01

# compare load strategies
python data_pipeline.py run \
  --load-strategy copy

    Honest limits

    • Not a privacy tool. It does not learn a distribution from real data and emit a private imitation. There is no real data anywhere in the process.
    • No GPU path, on purpose. Faker is pure Python over CPython's RNG with no CUDA path; a first CuPy call initialises the CUDA context in 0.5–2 seconds, more than the entire CPU cost of every numeric column combined; cuDF has no native Windows build. The run is bandwidth-bound anyway. The prediction, recorded before building it, is that a GPU path would be slower at this scale.
    • The loader opens one connection per table. Roughly 17 of the 35-second write step is handshakes. Reusing a connection is open work.
    • Parallel loading is implemented but unmeasured, and predicted to be close to flat.
    • The API serves only orders. Response models are hand-written, so a second api table is loaded but not exposed.
    • There is no CI.
