    Why it exists

    The engineering that matters only becomes visible at scale. A query plan at ten thousand rows and the same plan at ten million are different plans. Indexes that look pointless become load-bearing. Join order starts to matter, and so do cardinality skew, cache residency and the cost of a network round trip.

    The data that exhibits scale is held by organisations that will not release it. They publish papers about their scale, not the data behind it. So the ability to practise at scale ends up gated by employment. Making volume a parameter rather than a property of a handed-over dataset removes that gate.

    One dataset, five destinations

    Foreign keys survive leaving the database because every sink is materialised from a single in-memory dataset rather than generated per sink. The id a CSV row carries is the same object the PostgreSQL parent row carries. Select any stage.

    PostgreSQL

    Proven by the server, not asserted

    Constraints are created after the bulk load, so PostgreSQL validates every generated reference in one sequential pass. If generation were wrong, the constraint is refused and the offending row named.
